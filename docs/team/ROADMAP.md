# 神ゲープロジェクト ロードマップ

> **方針**: 監督が次の開発目標を提示し続ける。サイクルを区切らず継続実装する。
> ユーザの停止指示があるまで続ける。

## 神ゲー指針 (再掲)
1. 不確実性 > 計算可能性
2. 個に応じる世界
3. 協調の必然
4. テキスト RPG の格
5. 動かないものは作らない
6. 公平 (課金は強さに直結しない)

## 完了
- **Cycle 1**: 専門家 4 名による初回評価
- **Cycle 2**: 世界が個に応える + もう一戦の即効性 (`9e147ab`)
- **Cycle 3**: ハクスラドロップ + 装備システム (`e153983`)

## 進行・次サイクル

### Cycle 4 — 戦闘深度 (Combat Depth)
**理由**: Cycle 3 で導入した特殊効果が flavor のみ。これを実効化することで「装備を選ぶ意味」が完成する。
- クリティカルシステム (基礎 5% / 装備で +N%)
- ライフスティール (装備の `kind: lifesteal` を battle.ts が読む)
- 戦闘後リジェネ (装備 `kind: regen`)
- 敵カテゴリ (humanoid/beast/undead/magic/construct) に基づくスレイ・ボーナス
- 影響: 神ゲー指針 1, 2

### Cycle 5 — 呪い職を物語化 (Curse as Multiplayer Event)
**理由**: 呪い職は今ただの「強いけど戻れない罠」。協調の必然指針に応えるべく、解除フローを物語化する。
- 呪い職就業時に **サーバー全体告知** (「○○は呪いに身を落とした」)
- 解除には**他キャラ 3 人**が同じ街で解除儀式を実行
- 解除完了で**再びサーバー告知** (「○○は呪いから解放された」)
- 解除に協力した者には個別の称号 / アチーブメント
- 影響: 神ゲー指針 3

### Cycle 6 — 決闘 PvP UI (Duel as Discoverable)
**理由**: API が完成しているのに UI がない。Cycle 1 で技術エージェントが指摘した不一致解消。
- `/pvp` 改良 — 受信決闘リスト、相手検索、対戦結果表示
- 戦績ランキング (週次)
- 影響: 神ゲー指針 3, 5

### Cycle 7 — ボス戦 (Named Encounters)
**理由**: 通常戦闘と同じ画面で進行する強敵。"今夜のボス" がギルドの集合理由になる。
- Battle スキーマに `kind: "boss" | "normal" | "duel"` 追加
- ボス専用ドロップテーブル (legendary 確率上昇)
- ボス戦中の途中参加禁止フラグ実装
- 影響: 神ゲー指針 1, 3, 5

### Cycle 8 — シーズン自動切替 + WorldState
**理由**: 世界が毎日変わる→世界法則がシーズンで変わるサイクルを動かす。今は手動。
- 日次バッチ的な仕組み (Next.js cron 代替: 起動時のチェック)
- WorldState テーブルに今日の世界傾向を記録
- 街の rumorTrend が日次で揺らぐ
- 影響: 神ゲー指針 1, 5

### Cycle 9 — 攻城戦 MVP
**理由**: ギルドにとっての"目的"。世界に名を残す協調の頂点。
- Castle / SiegeEvent をスケジューラから起動
- 参加申請 → 戦闘 → 城所有
- 影響: 神ゲー指針 3

### Cycle 10 — 闘技場ランキング
**理由**: PvP の社会的フィードバック。レートとブラケット。
- Duel に rating 追加
- 週次ランキング表示
- 影響: 神ゲー指針 3, 5
